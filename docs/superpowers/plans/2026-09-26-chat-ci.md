# Chat-driven Model Efficiency CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Chat submit a unique Git request, have CI refresh/recompute a reproducible ladder, and read the exact result back without Notion or daily manual Actions operation.

**Architecture:** A request-only branch triggers a trusted Python runner using an immutable product commit. Source acquisition, scenario calculation, and Git publication are separate modules; results are append-only per request/run/attempt on a results branch. Chat reads instructions at one product commit and results at one publication commit.

**Tech Stack:** Python 3.11+ standard library, unittest, Git/GitHub REST, GitHub Actions, existing ladder_extra / frozen compute_frontier.

**Spec:** `docs/superpowers/specs/2026-09-26-chat-ci-design.md`

## Global Constraints

- Private repository: `ga815647/model-efficiency-frontier`; product branch main; result branch results. Do not overwrite any existing remote repository if the name is occupied.
- Existing run snapshots and `scripts/compute_frontier.py`, `scripts/ladder.py`, `scripts/recommend.py` remain byte-identical.
- GPT default ×18, Grok default ×16, Contributor ×1; one multiplier per row. Score descending; Claude comparison only, never a pick.
- floor has no global default: request requires min_score and nonempty min_score_reason. max_cost applies to adjusted cost, as current renderer does.
- Single benchmark/version/cost basis per calculation; preserve inferred public-version status and Contributor cache-write assumption. Never relabel API 4.3 as public 4.3.2.
- No secret values in requests, evidence, tracked files or logs. No credential recovery from session history in this task; AA_API_KEY provisioning is a separate owner step.
- Chat tool visibility, actual call success and project E2E success have separate evidence records. No assertion that a Git push installs Project settings.
- Full suite command: `python3 -m unittest discover -s tests -v`. Production source fetching is not a unit-test dependency.

## Review Focus

1. Malformed JSON values including booleans-as-numbers, duplicate keys and nonfinite values must fail before execution (Task 1).
2. A candidate family disappearing due to source-page changes must fail with evidence, not silently shrink the table (Task 3).
3. Source CSV and report must not be mixed between version/provenance or calc calls, including zero paid candidates (Tasks 2/4).
4. Retries/concurrent runs must preserve both attempt directories and not move latest pointers backwards (Task 5).
5. Failed execution, failed publication, or lost Chat write response must not return an older success as the new result (Tasks 6/7).

def finite_number(value, *, positive=False):
    if type(value) not in (int, float) or not math.isfinite(value):
