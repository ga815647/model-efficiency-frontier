## 2. 全流程逐行擾動（154×正負＝每組308個情境）

每次只動一個候選的一個數字，從全154行重新跑CP鏈及精簡。

| 假設變更 | 改變最終名單的情境數 | 具體影響 |
|---|---:|---|
| Score ±0.1 | 2/308 | Astra medium降0.1、或Sol max升0.1，均少留Astra medium |
| Score ±0.25 | 4/308 | 前兩個邊界案例，加上Astra max升0.25、Astra xhigh降0.25 |
| Cost ±1% | 0/308 | 名單不變 |
| Cost ±5% | 2/308 | Astra high降價5%、或Astra medium漲價5%，均少留Astra medium |

不能用「306/308不變」宣稱99%穩定：多數被擾動行原本遠離推薦邊界，情境也沒有機率權重；以上不是聯合或相關誤差測試。

### 需要重視的連動

- **Astra max升0.25分**：第一階段19點成員不變，但第二階段由Astra xhigh／medium改為max／high。只一個數值變動就換了兩個代表。
- **Astra xhigh降0.25分**：第一階段成員也不變，第二階段由xhigh改max，medium仍保留。
- **Astra high便宜5%**：medium在第一階段已不再是CP新高；這個变化不能全部歸咎第二階段。

轉折公式除以相鄰分差，原Astra max→xhigh只有0.287342分。這種很短的區段會放大分數變化對轉折強度的影響，再由貪心剔除與新鄰點傳遞。雖然本次大部分候選沒動，仍不足以宣稱核心強檔選擇穩健。

另做隔離第二階段的19點擾動：每組38情境；分數組各有4個情境破壞原分數／CP單調次序，因此明列skip，不偷偷重排成另一條有效CP鏈。成本±5%的隔離試算與全流程結果不同，正好說明不可只在固定鏈上擾動來推論正式全流程穩定性。詳情保留在JSON。

## 3. 端點、順序及覆蓋

- 中性端點改為−1／0／+1，在**本快照**結果相同，未證明其他資料亦然。
- 每次刪除後重算與只用初始k值相比，非Claude名單相同；Claude比較檔由max改xhigh。說明鄰點重算是算法的一部分，不能任意省略。
- 20次固定seed打亂輸入順序，基準結果皆相同；這只檢查輸入排列，不證明貪心為全局最優。
- 試算驗證最終Score下降、CP上升、相鄰分差至少替代範圍，每個原鏈點有距離小於範圍的最終代表。
- 人工三點例子Score=10/9/6、CP=1/3/4會留下middle/tail而刪top，驗證最高分沒有被固定保送。這不是模型數據，也不證明端點0有客觀最優性；只剩兩個相近端點時，0平手再依CP仍會選較低分者。

## 結論及下一步建議

**保留使用者接受的2分替代原則；不建議現在把這個未平滑的轉折公式直接定版。** 門檻邊界是硬門檻的必然取捨，但Astra強檔在0.25分擾動下連動改選，顯示以極短區段斜率作強弱依據仍待改進。

下一個候選方向應針對極小分差的放大效應，仍在同一混合CP链直接選代表，再用同組擾動比較；不能為了固定這張10點表反覆調參，也不能以永遠保留最高分或一律挑便宜代替。尚未批准新的公式、正式spec或實作計畫。
